# Outputs Guide

This guide explains where outputs are written and what each file contains.

## Run bundle (single simulation)

Common files:
- `fields.npz`: core arrays (`C_snap`, `D`, `k`, `patch_mask`, `t`, `J`).
- `meta.json`: grid/boundary settings and stability info.
- `metrics.json`: permeability, lag time, and flux stats.

Optional files (when generated by `run_sim` and validation scripts):
- `diagnostics.json`: mass and min(C) over time.
- `bc.json`: donor concentration over time (`Cpatch`).

## Figures

- `figures/validation/v1`: V1 heatmaps and depth profiles.
- `figures/validation/v2`: D/k maps and time series plots.
- `figures/validation/v3`: patch geometry and heterogeneity plots.
- `figures/validation/v1_convergence.png`: grid refinement errors.

## Datasets

- `outputs/sim/v3_literature_dataset_v1/dataset/run_###/`: per-run bundles for ML.
- `data/processed/id/`: ID train/val/test splits.
- `data/processed/ood/`: OOD holdout split.
- `data/processed/index.json`: split summary and index mapping.
- `data/processed/ml/`: ML-ready exports (`X`, `y_scalar`, `J`, `t`) and `meta.json`.

Notes:
- `assemble_dataset --lightweight` writes processed split files with only `J` and `t`.
- `export_ml_dataset` still works in lightweight mode because tabular features come
  from per-run `meta.json` and D-field summaries read from each run bundle.
